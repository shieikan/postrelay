# 利用・運用ガイド

LinuxのDocker構成は[サーバー起動ガイド](server.md)、通知データの形式は[通知元の仕様](notification-source.md)を参照してください。

## GUIで設定する

最初の「Discordへの通知」画面で、Xアカウントと届けるチャンネルの組み合わせを確認し、通知を停止・再開します。「オン」は通知する設定であることを示し、接続の正常性や送信成功を保証する表示ではありません。

「通知するアカウントを追加」または「編集」で、Xのユーザー名・表示用のチャンネル名・Discordの送信先URLを設定します。チャンネル名だけを変えても送信先は変わりません。Webhook URLが未設定なら送信できません。

キーワード、返信・リポスト、ロールへのメンションは「通知する内容・メンション」から設定します。含める言葉のどれか1つを含めば対象になり、空欄なら絞り込みません。除外する言葉のどれか1つを含む通知は送信せず、両方に一致した場合も除外を優先します。メンションは初期状態で無効です。

Angelic-Angelの受信が有効な環境では、種類を区別できないことを設定画面に表示します。「投稿の種類で絞り込まずに通知する」を確認してから保存してください。旧設定が種類の絞り込みと一致しない場合は、一覧で「通知内容の確認が必要」と表示します。通知元が正規化JSONを送る環境では、個別の返信・リポスト設定を引き続き使えます。

「送信履歴」で、対象になった通知と結果を確認できます。「送信済み」はDiscordが受け付けたことを示し、メンバーの閲覧を示しません。日時はPostRelayが受信した時刻です。表示・検索は全通知設定の最新100件から行い、アカウントごとの絞り込みもその範囲が対象です。チャンネル名は現在の設定を表示し、過去に実際に送信した宛先を記録しているわけではありません。

「設定」で投稿通知の受け取り方法とDiscordへの送信先を確認します。受け取りURLを作り直すと以前のURLは使えないため、接続したツールのURLも更新してください。すべての送信履歴とログアウトも、この画面から操作できます。

## Pythonで起動する

Python3.9以降と、このリポジトリが必要です。外部Pythonパッケージは使いません。リポジトリ内で実行します。

```sh
python3 -m postrelay --mode selfhost --data-dir ./data
```

ブラウザーで[http://127.0.0.1:8765](http://127.0.0.1:8765)を開き、PostRelayのアカウントを作成します。パスワードは12文字以上です。メール確認・パスワード再設定は未実装です。

キーを知っている人だけにアカウント登録を許可するには、同じシェルで次のように起動します。

```sh
export POSTRELAY_SIGNUP_KEY="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
python3 -m postrelay --mode selfhost
```

この例で生成したキーはシェルの環境変数に保存されます。自分のターミナルで値を確認し、アカウント作成時の登録キー欄へ入力してください。キーやX Cookieを公開ログ・Gitへ含めないでください。

初期状態は動作確認モードで、Discordへ送信しません。実送信を有効にする場合は`--live`を付けます。

```sh
python3 -m postrelay --mode selfhost --live --data-dir ./data
```

実送信が有効なら、通知設定のWebhook URLへ送信します。送信先が未設定なら失敗として記録します。動作確認の記録は「送信なし」で区別します。X通知を直接受け取る場合は、別途[通知元の接続](notification-source.md)が必要です。

## 保存と再送

- 同じPostRelayアカウント内の同じ投稿IDは、一度だけ送信キューへ登録します。
- 通知と送信待ちの保存後に、通知元へHTTP202を返します。
- HTTP429は`retry_after`を待ち、通信失敗と5xxは指数バックオフで再送します。最大8回で失敗となり、GUIから手動で再試行できます。
- 未完了の送信はSQLiteに保存し、再起動後も継続します。期限切れの処理リースは再取得します。
- Discordへの送信成功直後・DB保存前に停止すると、再送で重複する可能性があります。常に1回だけ届ける保証はありません。
- 通知元が再送しない受信前の失敗は回収できません。同梱のAngelic-Angel修正パッチは非2xx応答を成功扱いしないようにしますが、通知元の永続再送やMozillaの再配信を保証しません。

## 利用上限

処理量を抑えるため、全アカウントで同じ上限を設けています。通知設定は最大2000件、1件の設定では2つの欄を合わせてキーワード100個までです。同じXアカウントを別のチャンネルにも設定すると、それぞれ1件と数えます。旧プランのデータも、通知設定・履歴を保持して共通の上限へ移行します。

## 接続情報とプライバシー

パスワードはPBKDF2-SHA256、セッション・受信トークンはSHA-256のダイジェストで保存します。Webhook URLは送信に必要なためDBへ保存します。DBは0600、新規データディレクトリは0700ですが、DB自体は暗号化されていません。バックアップにもアクセス制限を適用してください。HTTPログへCookie、本文、リクエストパスは出力しません。

Discordへ送るのは対象投稿者の公開本文と投稿リンクです。通知を受け取るXアカウントの名前、Cookie、PostRelayのメールアドレスや内部IDを含めません。通知形式確認用の生データもDiscordへ転送しません。DiscordでWebhookを作成したユーザーは、管理権限で確認できる場合があります。

Cookieを含むAngelic-Angel設定、Webhook URL、DB、生通知、実運用ログをGitへ追加しないでください。`.gitignore`は一般的な保存先を除外しますが、任意のファイル名に保存した秘密情報を自動検出するものではありません。

## 運用の範囲

アカウントごとに永続データを分離しますが、同じプロセス・DBを共有するため、資源の隔離や大規模ホスティングへの耐性は保証しません。通知・送信履歴の自動削除は未実装で、継続保存されます。運用前に容量・保持・削除の方針を決めてください。

少人数のセルフホスト向けです。インターネット公開には、HTTPS、登録制御、バックアップ、アカウント復旧、監視、負荷・運用検証が必要です。公開URLを指定するだけで運営可能になるわけではありません。[現在の検証範囲](../VERIFICATION.md)を参照してください。
