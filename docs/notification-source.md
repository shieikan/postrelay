# 通知元の仕様

サーバーのX接続手順は[サーバー起動ガイド](server.md)を参照してください。この文書は、受け取るデータと送信対象の仕様を説明します。

## Angelic-Angelの公開投稿確認

[Angelic-Angel](https://github.com/sh1ma/Angelic-Angel)が受信したWeb Pushの`data.url`または`data.uri`から公開投稿リンクを読み、[Xの公開oEmbed](https://docs.x.com/x-for-websites/oembed-api)で投稿ID・投稿者・本文を確認してから転送します。通知に含まれる本文や名前は送信に使いません。DM、別投稿者、不一致のURL、公開確認できない通知は送信対象外です。

oEmbedでは返信・リポストの種類を確認できません。通知設定画面で説明を読み、「投稿の種類で絞り込まずに通知する」にチェックして保存してください。この確認で内部の返信・リポスト設定が両方オンになります。既存設定でどちらかがオフなら、一覧に「通知内容の確認が必要」と表示し、種類不明の投稿は送りません。他人が投稿したリポストを対象投稿者本人の投稿として転送することもありません。

Docker構成では、通知元が共有ネットワーク内のループバック受信口へ接続します。GUIのWebポートでは生のX通知を受け付けません。Pythonで同じPC内に受信元を置く場合の起動例です。

```sh
python3 -m postrelay --mode selfhost --live --relay-web-push
```

GUIの「設定」→「投稿通知の受け取り方」で作成したURLの`/api/hooks/`を`/api/push/`に変更し、Angelic-AngelのWebhook送信先に設定します。認証トークンは変更しません。Dockerの場合は[対話式の接続手順](server.md)を使ってください。CookieはAngelic-Angelの非公開設定へ保存し、PostRelayの管理画面へ入力しません。

## 初回の通知形式を確認する場合

生通知の保存は初期状態で無効です。保存内容に同意した本人のセルフホスト環境でだけ、`--capture-push`を追加してください。ループバック受信口の認証済み通知を非公開DBの`push_inbox`へ保存します。受け取りURLを作り直すと、以前のトークンは失効します。

- ユーザーごとに最新20件、24時間まで保存します。稼働中のワーカーが約1分ごとに期限切れを削除します。
- 停止中は削除も停止し、再起動後の削除までDBに残ります。
- `--capture-push`だけなら保存後にHTTP202を返し、Discordへ転送しません。
- `--relay-web-push`も有効なら、公開確認できた通知を転送し、確認できなかった通知だけを保存します。
- 保存後に公開確認を自動で再試行する機能はありません。生データはGUIやDiscordへ表示しません。

通知に非公開情報や別アカウントの情報が含まれる可能性があります。通知元の復号鍵・Cookie・生データを公開ログやGitへ含めないでください。

## 他の通知ツールを接続する

GUIで作成した受け取りURLを、信頼できる通知ツールのWebhook送信先へ設定します。URL自体が認証情報です。作り直すと以前のURLは使えなくなるため、ツール側も更新してください。

次のJSONを受け付けます。アカウントと投稿は架空です。

```json
{
  "id": "12345",
  "author": "demo_studio",
  "text": "新機能を公開しました。",
  "url": "https://x.com/demo_studio/status/12345",
  "kind": "post",
  "visibility": "public"
}
```

| 項目 | 条件 |
|---|---|
| `id`、`author`、`text`、`url` | 必須の文字列。投稿ID・ユーザー名とURLが一致すること |
| `text` | 1〜4000文字 |
| `kind` | `post`、`reply`、`repost`。省略時は`post` |
| `visibility` | `public`のみ。省略時も`public`として扱う |

この正規化JSONでは、URLとの整合性を確認しますが、公開範囲の自己申告だけで公開性が証明されるわけではありません。信頼できるツールから、公開投稿だけを送ってください。

別のJSON構造は、GUIの「連携ツールの詳細設定」で明示的に対応付けます。たとえば、`text`に`notification.body`を指定すると、その項目から本文を読み取ります。設定に一致しない通知はHTTP400となり、推測で送信しません。

全投稿の取得、全文・画像・動画の展開、通知元が送らなかったデータの回収は保証しません。接続元の固定版と変更内容は[連携パッチ](../integrations/README.md)、実際に確認した範囲は[検証記録](../VERIFICATION.md)にまとめています。
